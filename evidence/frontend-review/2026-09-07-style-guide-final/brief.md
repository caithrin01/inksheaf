# Inksheaf style guide: visual critique before building the site

The owner explicitly asked: assess the planning and make a style guide BEFORE the site itself. This is that standalone browser guide, not the next deployed site. We need judgment on the actual work, not validation of a brief.

Attached screenshots show the new primary identity, its small/reversed masters, four covers of the SAME real owner publication caithrin, a physical geometry specimen, the newsletter print-button sample, and mobile cover specimens. Previous rejected versions were beige literary-serifs and a separate wood/engraved desk panel. Primary references were Fitzcarraldo's top-down object photography, A24's quiet shop, Stripe Press's book dominance and We Made This's type-led Penguin covers. Do not claim those references approved this work.

New wordmark: Inter-derived heavy lowercase, square dot/stem i, redrawn open k, deliberate pair spacing; fully outlined. The favicon derives from the i. Serif alternative is labelled historical. Book fronts/spines must remain publication-owned. Caithrin's original Substack logo has a dark background and fine gold lines; do not recommend inventing a different mark. No other's-archive printing product. No foil/cloth claims. Covers are proposals pending integration into the existing versioned renderer.

The style guide's controls can switch all four covers to The Fox Says (real identity regression), a long fictional title and an unbroken fictional title, or omit logos and view grayscale. Existing geometry/fitting tests pass Chromium/WebKit at desktop/mobile, but they do not prove visual merit. The first model direction critique warned that grey + black grotesk alone could be generic, and that all four covers need actual layout differentiation. Those warnings informed the current guide.

Evaluate: 1. Is there a coherent, stronger direction or a polished generic presentation? 2. Logo legibility and distinctive qualities/remaining weaknesses. 3. Cover quality and actual differences; whether the tabletop contact looks credible. 4. The #FF6719 subscriber button uses dark text for AA and links to the owner's existing Lulu edition; does the context explain the core feature? 5. What MUST be corrected in the guide before it is used to build the site? Return a prioritized concise critique, concrete observations from the pixels, no more than 650 words. Distinguish blockers from preferences. Do not prescribe unrelated features or require a different tech stack.

The earlier call truncated and is not counted as a completed review. Its partial observations prompted explicit size labels, paths-vs-outline terminology, a defined serif editorial-lead role, deliberate logo plates, and a rebuilt down/right contact shadow with a side-profile construction diagram. The actual favicon CSS sizes are 16/24/32px; do not infer from a resized composite that they are equal. The final screenshots include these changes. Prioritize any remaining material blockers.
